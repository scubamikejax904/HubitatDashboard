# Plan: Update GPS Tracker Upload Logic

The goal is to modify the GPS upload behavior so that an upload is triggered when either the minimum distance threshold is met OR the configured time interval has elapsed.

## Current Context
- System uses a backend in `backend/src/`.
- `backend/src/gpsService.ts` handles fetching GPS data from a Google Sheet, but the actual logic for *creating* or *uploading* GPS data is not located in the `backend/` workspace.
- The phone (Pixel 9 Pro) is logging GPS data to a Google Sheet.
- The current implementation of `gpsService.ts` and `gpsRoutes.ts` only handles reading the data, not writing it.
- Inspection of the codebase does not reveal any internal GPS upload logic. It is highly likely the GPS upload logic is handled on the mobile device itself (e.g., via Tasker, or a dedicated Android app utilizing the Maker API).

## Assumptions
- The "GPS tracker" is a mobile-side component (e.g., Android Tasker task or a custom App) that sends data to a `/webhook` or similar endpoint on the Hubitat Dashboard backend.
- Modifying the "logic" will require finding the script or app responsible for the PUT/POST request to the server, as the server-side code I currently see only handles retrieval and filtering.

## Proposed Approach
1. Search for potential webhook handlers or API endpoints that accept GPS data (POST/PUT requests).
2. If the logic is on the phone side (likely), help the user identify how to update that script/app.
3. If the logic is server-side (yet to be discovered), update the logic to include a time-based check.

## Step-by-Step Plan
1. **Search for Webhook Handlers**: Scan `backend/src/` for any POST/PUT route handlers that might receive incoming data.
2. **Review Config Files**: Check if there are configuration settings related to time intervals or distance thresholds in `backend/config.json`.
3. **Clarify with User**: If no logic is found on the server, inform the user that the GPS upload logic likely resides on their mobile device and provide guidance on what to check (e.g., Tasker profiles, custom apps).
